How OSINT-Book works, in four steps

  1. You add one target and choose the sources. Before anything is sent, the app shows which value goes to which service.
  2. Every finding keeps its source link, retrieval time, an evidence excerpt with SHA-256 and your review status.
  3. Rule-based analysis turns findings into plain sentences marked Info, Attention or Missing, without any network request and without an overall risk score.
  4. Reports (PDF, HTML, JSON, CSV) keep every claim linked to its source.

04 / privacy and scope

Passive by design.
Honest about limits.

A query sends only the target value to the sources you selected. Everything else stays on your phone or your own server.

What it does

  • Shows before it sends. Which value goes to which service, before any query starts.
  • Keeps evidence. Source link, retrieval time, an excerpt with SHA-256 and your review status for every finding.
  • Protects keys. AES-GCM with Android Keystore on the phone, a server key vault on Windows.
  • Stays local. The Windows admin panel listens only on the server itself.

What it never does

  • No active attacks. No port scanning, exploitation, login bypass, file uploads or person profiling. Ping is the only active check and is never preselected.
  • No verdict. There is deliberately no overall risk score.
  • No keys in output. API keys never appear in reports or exports.
  • No internet exposure. The Windows user panel uses plain HTTP and is meant for a trusted local network only. IP geolocation estimates a network, not a person.
